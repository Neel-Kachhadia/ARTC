Role: Claude Sonnet 5.5 High, implementation and test review. Review the

This increment adds a BUILD_TESTING-only control seam for the existing
AttemptManager timer and dispatch paths, four forced timer/shutdown races, and
a seeded sequence that drives the manager's actual timer closures while
checking bounds after events. The production path still uses grpc::Alarm and
steady_clock when no test control is configured.

Control semantics in the current diff:
- Timer keys identify manager, kind and generation. The driver preserves
  cancelled timer closures so tests can deliver stale callbacks deliberately.
- Timer-ready checkpoints pause before AttemptManager takes its mutex.
- BeforeDispatchFence pauses under the manager mutex before taking the router
  dispatch mutex.
- InsideDispatchFence pauses after StartCall/attempt commitment while the
  dispatch mutex remains held.
- ShutdownFenceClosed signals after shutdown closes and releases the dispatch
  mutex, before it requests stop.
- The fake monotonic clock is shared by attempt/deadline/budget decisions.

The most recent Sol Max audit found no source defect in the dispatch fence, but
said the old seeded test did not force timer callback interleavings and checked
invariants only after requests drained. Sol High recommended injecting the
actual timer closures and pausing at both sides of the dispatch fence. The new
tests were built around that recommendation.
